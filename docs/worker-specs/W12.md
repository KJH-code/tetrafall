# W12 고도판 최적화 (계속) — 120fps+ (고사양) · 60fps (일반 노트북·내장 그래픽)
## 배경
재혁 결정: PC 가 주력, 성능 목표는 고사양 (RTX 5070 노트북, 2880×1800) 에서 120 이상, 일반 노트북·내장 그래픽에서 60. 같은 노트북에서 JS 웹판은 문제없이 돌고 고도 exe 만 느림 → 고도판 비효율. 이 컨테이너엔 GPU 가 없어 렌더 ms 는 소프트웨어 렌더(llvmpipe)라 믿을 수 없지만, **GDScript 시간·물체 수·그리기 호출·삼각형·SubViewport 수·픽셀 채움 비용(해상도에 비례하는 패스 수)** 은 근거 있게 줄일 수 있다.
이미 한 것 (먼저 읽기): W6 가 `godot/README.md` 의 perf 절·world/gfx_calc.gd·world/gfx.gd·core/ 의 F3 패널·autopilot `--perf-log`·`world/perf_ab.gd --ab` (한 판 안에서 설정을 번갈아 재기)·`tools/perf_cmp.cjs` 를 만들었고 화질 선택(자동·높음·보통·낮음, 3D 해상도 배율·MSAA·거울 반사)을 넣었다. W7 은 탱크 몸을 .glb 로 구워 조립 13.9ms→0.67ms, 뼈 90→27 (chars/BAKE.md — 나머지 7명은 둘째 표면 문제로 미완). W6 감사의 수치 (xvfb 1280×720 높음): 판 8명 = 스크립트 23.2ms (몸 자세 4.2·스냅샷 JSON 3.2·HUD 1.5 …), 그리기 294, 삼각형 215k, 물체 664, SubViewport 1 (1인칭 팔 1280×720 4×); 대기실 = 그리기 261·SubViewport 3 (팔·거울·큰 캐릭터); 타이틀 = 거울 SubViewport 1 (창의 반) + 글로 5단.
## 목표
1. **8명 판 스크립트 시간 23ms → 6ms 이하** (이 컨테이너 기준, 부하 평균이 높으니 같은 조건 A/B 로): 몸 자세 갱신 (화면 밖·멀리 있는 사람은 낮은 빈도 LOD, 뼈 맞추기 최소화), 스냅샷 JSON 해석 (30Hz — 바뀐 것만 반영·다시 만들지 않기·Dictionary 복사 줄이기, 필요하면 WorkerThreadPool 로 파싱하되 순서·결정성 유지), HUD 갱신 (바뀔 때만), 보간·래그돌 (모터 PD 계산 비용, 화면 밖 래그돌 끄기), _process/_physics_process 호출 수 (노드마다 따로 도는 것을 한 곳에서 돌리기), 매 프레임 할당 (Array/Dictionary/문자열 만들기) 제거. 프로파일 근거 (Time.get_ticks_usec 구간 · 고도 내장 프로파일러 · `core/prof.gd`) 와 전/후 표.
2. **그리기·픽셀 비용 (GPU 쪽, 구조로 줄이기)**: 그림자 (해 그림자 지도 크기·캐스케이드 수·거리), 외곽선 패스 (고도에서 어떻게 그리는지 — 몸마다 역 메시 두 번 그리기라면 셰이더 한 패스/면 뒤집기로, 비용 비교), 떨어지는 블록·지형 인스턴싱 (MultiMesh), 투명 객체 정렬·오버드로 (판 빛 LUT·위험 액체 셰이더의 프래그먼트 비용: 라이트 루프·텍스처 읽기 수), 전체화면 후처리 패스 수, SubViewport (팔·거울·큰 캐릭터·초상) 의 갱신 모드·크기·MSAA. 해상도에 비례하는 패스를 3D 해상도 배율 (W6 의 gfx) 로 묶어 2880×1800 에서 자동 '보통' 이 합리적으로 보이게 (모습 변화는 전/후 화소 차로 확인, 보통 화질의 모습을 눈에 띄게 바꾸지 않기).
3. **렌더러 비교 준비 (결정은 재혁 PC 숫자로)**: PC 만 Forward+/Mobile 을 쓸 수 있는지 — 한 프로젝트에서 `rendering/renderer/rendering_method` (PC 기본) 와 `rendering_method.web = gl_compatibility` 로 나누기, 우리 셰이더 (shaders/, world/*.gdshader, title/*.gdshader, 툰·g3 전역값) 가 Forward+·Mobile 에서도 컴파일되는지 (이 컨테이너에 Vulkan 이 있는지 `vulkaninfo`/lavapipe 확인 — 있으면 `--rendering-method forward_plus --rendering-driver vulkan` 로 xvfb 실행, 없으면 셰이더 파일 정적 점검·Godot `--check-only`/`--headless` 로딩만), 실행 인자 `--rendering-method` 로 바꿔 켤 수 있게 배포 묶음 (godot/server/tools/package.mjs) 에 `start-lan-forward.bat`·`start-lan-mobile.bat` 같은 시험용 실행 파일 (렌더러만 다름) 을 추가하고 F3 한 줄 (이미 렌더러·어댑터 이름이 있음) 로 재혁 PC 에서 각각 FPS 를 재서 보내 주게. 기본값은 지금대로 (gl_compatibility) 두고 재혁 숫자 뒤 결정. 문서 godot/README.md 에 한 절.
4. 결과를 항목별 '전/후' 표 (스크립트 ms 항목별·그리기·삼각형·물체·SubViewport·영상 메모리) 로 정리하고, 아직 남은 큰 비용과 다음 후보를 순위로 (프로파일 근거).
