# W41 — 렉 사냥: 메뉴 직후·판 시작 직후·블록 이벤트(낙하 시작·갈고리 궁·탱크 궁 …) 때 렉

재혁 (2026-11-10) "지금 최적화 시작할 때 너무 렉걸림". 인터뷰 답: 렉이 나는 시점 =
 (a) **게임을 켠 직후 메뉴 (몇 초~십몇 초)**, (b) **판 시작 (카운트다운) 직후**, (c) **블록 관련 이벤트 때 (블록 낙하 시작, 갈고리 궁, 탱크 궁 등)**. 설정은 건드린 적 없음 (자동: '3D 해상도 자동' 켬·화질 자동). 재혁이 쓴 버전 = v0.1.15 (작업 브랜치 694d84a). 이 브랜치 `w/W41` 은 `w/W39` (영상 메모리·LOD 텍스처 지연 로드·칸 LOD 등, 아직 작업 브랜치에 미병합) 위 — W39 변경도 의심 대상이라 같이 본다.
**v0.1.11~v0.1.15 에서 내가(워커들이) 넣은 '최적화' 가 오히려 렉의 원인일 가능성이 높다**: 그 일의 공통점 = **처음 쓸 때 한꺼번에 하는 일** (미리 읽기·미리 그리기·지연 로드·첫 사용 셰이더·텍스처 생성). 추측 금지, 시점별로 **CPU ms 를 재서 원인을 확정**하고 고칠 것. 같은 시각 W40 이 `chars/ext_cloth.gd`·`ext_clips.gd`·`ext_motion.gd`·`viewmodel.gd` 팔 모션·`tools/blender/tripo/` 를 만짐 — 그쪽은 건드리지 말 것. 서버 판정·규칙 금지.

## 의심 목록 (측정으로 확정)
1. **(a) 메뉴 직후**: W30 의 `External.request_all` (메뉴에서 쉴 때 모든 .glb·클립을 스레드로 읽기) + `warm_step` (캐릭터마다 몸을 아주 작게 두 번 그려 셰이더·메시를 올리기) 가 한 프레임에 몰리거나 메인 스레드를 오래 잡음. `G3.prewarm`·`prewarm_lobby` (가짜 대기실 8명을 두 번 그림)·`warmPortraits` (초상 8장)·음악 지연 로딩과 겹쳐 메뉴에서 수 초~십수 초 끊김. 그 동안 사용자는 이미 메뉴를 만지는 중. → 작업을 **프레임당 시간 예산 (예: 2~3ms) 안에서 한 조각씩** 나누고, 입력·마우스 이동·화면 전환이 있으면 쉬고, 판 시작 전에 다 끝나야 하는 것과 나중에 해도 되는 것을 구분 (우선순위: 내가 고를 캐릭터 > 방 입장에 필요한 것 > 나머지).
2. **(b) 판 시작 직후**: 몸 8개 만들기 (W32 분산: 프레임당 2개), **W39 의 알베도 지연 로드** (몸 만들 때 `ResourceLoader` 로 텍스처 동기 읽기 — 미리 안 읽었으면 몸당 수십 ms), W31 **적응형 해상도** 가 시작 직후 프레임 스파이크 (로딩 때문에 느린 프레임) 를 GPU 병목으로 오판해 배율을 내렸다 올렸다 하며 3D 버퍼를 다시 만들어 더 끊김 (→ 시작 후 N초 유예·스파이크 무시·내릴 때만 느리게), 카운트다운 중 월드 적용 (`world.apply`·지형 칸 만들기·테마 텍스처·위험 표면 `hazard_view`), 칸 LOD 모양 처음 만들기 (W39).
3. **(c) 블록 이벤트·궁**: 처음 쓰일 때 만드는 것들 — **블록 낙하 시작**: 칸 모양 메시·재질·그림자 상자 MultiMesh·칸 LOD 모양 생성 (W32·W39), 착지 이펙트; **갈고리 궁 (R 덩어리)**: W35 의 `world/chunk_tex.gd` 가 **처음 쓸 때 절차적 텍스처를 만들 가능성** (돌·모래·판자·테마 칸 재질) + 하늘 블록 반투명 재질; **탱크 궁 (솟는 땅)**: 같은 `chunk_tex` 돌 질감 + 솟는 땅 메시/파편; 건축가 블록·대포 폭발 (화염구·충격파·연기·파편 풀); 이펙트 `fx/` 의 처음 쓰는 재질·셰이더 (G3 prewarm 이 이 변형까지 덮는지). 8명 모두의 궁·스킬 (`fx_config`) 을 하나씩 처음 발동했을 때 CPU ms 표.
4. 그 밖: W35 반투명 깊이 패스 재질 (유령화·무적 처음 켤 때 셰이더), W40 천 시뮬 (아직 미병합이라 영향 없음), 초상 캐시, `hitch` 로거 자체 비용.

## 할 일
1. **재현·측정 (핵심)**: 소프트웨어 렌더에서도 믿을 수 있는 것 = **함수별 CPU ms (첫 호출 vs 두 번째 호출)**. 시점별로 스크립트에서 구간 시간을 재서 표 (`Time.get_ticks_usec`, `Prof`, 히치 로거 `core/hitch.gd` 확장):
   - **메뉴 시작~30초**: 프레임별 메인 스레드 사용 ms 의 시간 흐름 (프레임 시간 > 25ms 인 프레임 수·최악 ms·어느 단계 (request_all / warm_step / prewarm_lobby / 초상 / 음악) 가 차지하는지) — 소프트웨어 렌더라 렌더 ms 는 버리고 **스크립트 CPU ms** 만.
   - **방 만들기→판 시작→카운트다운 5초**: 프레임별 CPU ms + 단계별 (몸 만들기·텍스처 읽기·world.apply·hazard·칸).
   - **이벤트 첫 발동 vs 두 번째 발동 표**: 블록 낙하 시작·착지, 8명 캐릭터 각각의 스킬·궁 (탱크 R·갈고리 R·건축가 R·대포 R·바드·광전사·닌자·사냥꾼), 유령화·무적, 아이템 줍기, 폭탄, KO 연출 (스매시 줄기·슬로모션), 압사 — 첫 호출 ms − 두 번째 호출 ms = '처음 쓰는 값'. 큰 것 (10ms 이상) 이 렉의 후보.
   - 재연 도구 (`replay`·`rec_chars`·`rec_loop`·`game8.rec`·`--budget`·`--census`·연습 방 `--practice` 로 스킬 연속 발동 `autopilot`) 활용. 재현이 안 되면 그 사실과 근거를 보고.
2. **고치기 (원인별, 모습·규칙 불변)**: 큰 것부터 —
   - 메뉴 전처리를 **프레임 예산 스케줄러** (`world/prewarm_sched.gd` 같은 한 곳: 작업 큐 + 프레임당 예산 + 우선순위 + 입력 중 쉼 + 취소) 로 바꿔 한 프레임에 몰리지 않게.
   - **첫 사용 값을 판 시작 전에 (대기실·메뉴에서) 미리**: 이펙트 재질·절차적 텍스처 (`chunk_tex`)·칸 모양 메시 (테마별)·궁 이펙트의 셰이더 변형·반투명 깊이 패스 재질 — 숨은 곳에서 한 번 그려 컴파일 (`G3.prewarm` 목록 확장, `shader_check.gd` 목록과 일치), 한 번에 하지 말고 스케줄러로 쪼갬.
   - **W39 지연 로드가 판 시작 때 동기 읽기를 일으키면**: 대기실에서 참가자 목록의 캐릭터 LOD 텍스처를 스레드로 미리 요청 (`load_threaded_request`), 판 시작 시점에 이미 캐시에 있게. 판 중 처음 나오는 캐릭터 (대기실에 없던) 는 몸 만들기를 한 프레임 미룸.
   - **적응형 해상도**: 판 시작·몸 만들기·카운트다운 후 N초 (예: 4초) **유예 (ceiling 고정)**, 스파이크 프레임 (직전 중앙값의 3배↑) 은 판단에서 제외, 배율 변경은 그 프레임에 다른 큰 일이 있으면 미룸, 한 번 바뀐 뒤 최소 유지 시간. 히치 로거 `해상도 변경` 태그가 판 시작 직후 몇 번 찍히는지 재연에서 확인.
   - 판 시작 직후 한 프레임에 몰리는 일 (world.apply·hazard·몸·초상) 을 프레임에 걸쳐 분산.
3. **히치 로거 강화 (재혁 PC 에서 원인 확인용)**: 평소엔 꺼도 되지만 **F3 없이도 `--hitch` 로 기록**되는 기존 로그에 '직전 100ms 안에 있었던 일' 태그를 더 상세히 (이벤트 종류: 블록 낙하 시작·R 궁 종류·스킬·판 단계·몸 만들기 캐릭터·셰이더/텍스처 첫 사용 이름), 한 판 끝에 '히치 원인 상위 5개 + 최악 ms + 시점' 요약을 `user://hitches.txt` 와 F3 에 (이미 있으면 확인). 재혁이 한 판 뒤 그 파일의 요약만 붙여 주면 원인이 보이게.
4. **전후 표**: 시점별 (메뉴 30초 / 카운트다운 5초 / 이벤트 첫 발동) **프레임 스크립트 CPU ms 최악·95백분위·25ms 초과 프레임 수** + '처음 쓰는 값' 표. 소프트웨어 렌더 한계 (렌더 ms 불신, 셰이더 컴파일은 GL 드라이버라 CPU ms 로 잴 수 없음 — 대신 **셰이더 첫 사용을 prewarm 이 덮는지 목록 비교** 로 검증) 명시.
