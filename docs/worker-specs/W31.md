# W31 — 최적화 2차: 지속 비용 (GPU 쪽) 줄이기 — 적응형 해상도·판 LOD 다시 굽기·외곽선 거리 끄기

재혁 (2026-11-08): "계속 최적화 해". 1차 (W30, v0.1.11): 새 모델 순간 끊김 (모델·텍스처 읽기·첫 그리기) 고침 + 히치 로거. **남은 것 = 지속 비용 (GPU 쪽)** — 재혁 F3 숫자는 아직 없음 (RTX 5070 + 내장 하이브리드 노트북, 2880×1800, Windows 배율 200%). 소프트웨어 렌더 환경이라 GPU ms 는 못 재니 **그리기 수·삼각형·영상 메모리·픽셀 수** 로 환산하고, 재혁 PC 에서 스스로 조절하는 **적응형** 장치를 만들 것. 브랜치 `w/W31` (= 작업 브랜치 823b52b, v0.1.11).

## 현황 (W30 측정)
- 8명 판 삼각형 208k (새 모델 ≈ 몸 하나 26.7k = 색 + 외곽선 껍질 + 그림자) vs 예전 몸 165k. 새 모델 판 LOD 가 ~8.5~9천 아래로 안 내려감 — Tripo UV 조각이 잘게 나뉘어 meshopt 가 이음선을 못 넘음 (위치 8875 vs 정점 23270). 사냥꾼은 UV 이음선이 덜 잘려서 3~5천까지 내려감.
- 외곽선 껍질은 그림자 패스에서 이미 빠져 있음. 그리기 호출은 새 모델이 오히려 줄었음.
- 화질 프리셋 (`world/gfx_calc.gd`, 높음 MSAA 4×·보통 2×·낮음 끔) 은 있으나 **프레임 시간을 보고 스스로 조절하지는 않음**. 3D 해상도 배율은 수동/자동 (고정 규칙).

## 할 일
1. **적응형 해상도 (동적 해상도)**: 프레임 시간 (`core/prof.gd`·`hitch.gd` 가 이미 프레임 간격을 앎, 렌더 CPU/GPU 구분은 `Performance.get_monitor(TIME_*)`·`RenderingServer` 프레임 시간) 을 보고 **GPU 가 병목일 때만** 3D 렌더 배율 (`Viewport.scaling_3d_scale`, FSR/bilinear 업스케일 `scaling_3d_mode`) 을 0.6~1.0 사이에서 서서히 (히스테리시스: 내릴 땐 빠르게, 올릴 땐 천천히·여유 두고) 조절. 목표 프레임 시간은 모니터 주사율/60Hz 기준 (V-Sync 켜짐이면 16.6ms), 판 중에만, 대기실·메뉴는 고정. 설정 창 '3D 해상도' 에 '자동 (적응)' 추가, 새 설치 기본 켬 (이미 값을 저장한 사용자는 존중). UI 는 해상도와 무관 (2D 레이어는 원본 해상도 유지), 초상·HUD 안 깨지게. 순수 계산 (`world/` 아래 새 `adapt_calc.gd`: 입력 프레임 ms 열 → 다음 배율, 테스트로 오르내림·히스테리시스·바닥·천장) 은 헤드리스 테스트.
2. **판 LOD 다시 굽기 (삼각형 ~9천 → 3~5천)**: 닌자·탱크·갈고리 판 LOD (high/medium/low) 를 **새 UV 로 재전개 + 알베도 재굽기**로 만들어 이음선 한계를 없앤다. Blender (`tools/blender/tripo/`, 이미 `lods.mjs`·`rig_*.py` 있음) 에서: 고해상 (stage = 원본 1.7~1.9만) 메시 → Decimate (Collapse, 가중치·UV 경계 보존 끔) → Smart UV Project/Unwrap 으로 **큰 조각 몇 개로** → Cycles CPU 로 원본 알베도 텍스처를 새 UV 로 굽기 (`bake_type=DIFFUSE` 직접 칠함/`selected_to_active`, 2048→1024 판 LOD 전용 아틀라스), 스킨 가중치도 Data Transfer 로 옮겨 stage 와 같은 뼈에 묶음. 팀 색 칸 (`tint:"mask"` UV2/마스크) 도 같이 옮겨야 함 — 마스크를 같은 방식으로 굽거나 새 UV 에서 다시 정의. `.json` 의 `lods` (stage/high/medium/low) 에 새 메시 연결, 판 LOD 별 아틀라스 파일. 사냥꾼은 이미 3~5천이라 건드리지 않음. **시각 회귀 확인** (4명 판 거리에서 구멍·찢김·색 번짐·팀 색 칸 없음). 못 하면 (스킨/마스크 옮기기 실패) 그 사실과 이유를 보고하고 건너뜀.
3. **외곽선 거리 끄기**: 외곽선 next_pass 로 몸이 2번 그려짐. 카메라에서 일정 거리 (판 크기·카메라 기준, 설정 `OUTLINE_FAR`) 넘으면 외곽선 끄기 (`VisualInstance3D.visibility_range_*` 로 외곽선 껍질만, 또는 재질 next_pass 교체) 와 화면에서 작을수록 굵기 줄이기 — 먼 몸은 예전 모습과 시각 차이가 적은 거리부터 (`pose_lod.gd` 거리와 맞춤). 가까운 몸·1인칭·대기실은 그대로.
4. **그 밖의 지속 비용 점검 (측정 후 효과 큰 것만)**: 텍스처 밉맵·이방성, 그림자 맵 크기·거리 (`world_config`), MSAA 가 높음에서 2880×1800 에 미치는 픽셀 비용 → 해상도 배율과 함께 자동 조절 규칙에 포함, 8명 판 재질 수/상태 변경 (같은 재질 공유), 위험 액체·하늘 구 같은 월드 쪽 큰 비용 (`world/` 구간 `prof`).
5. **측정·보고**: 전후 표 (삼각형·그리기 수·영상 메모리·판 LOD 별, 소프트웨어 렌더 프레임은 참고만). 적응형 해상도는 **가짜 GPU 부하**로 시험: 헤드리스에서 프레임 ms 열을 흉내내 (또는 `GLSTUB`/`--gpu-load` 같은 인공 지연을 `RenderingServer` 쪽이 아닌 계산기 입력으로) 오르내림이 안정적인지 (진동 없음) 확인.
