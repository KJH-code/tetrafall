## 원인 후보 (측정으로 가를 것)
A. **지속 비용**: 새 판용 LOD 가 몸 하나 ~8.5~9천 삼각형 (예전 ~1.3천) → 8명이면 ~7만 + **외곽선 next_pass 로 2배 그림** + 스킨 메시 8개 + 텍스처 2048² × 최대 8 (캐릭터별 1장) 영상 메모리. 그림자 패스에도 다시 그려지는지 (외곽선 껍데기를 그림자에서 뺀 기존 최적화가 새 모델 재질에도 걸려 있는지), 2880×1800 에서 픽셀 비용, MSAA.
B. **순간 끊김 (히치)**: ① **처음 보는 모델·재질의 셰이더 컴파일** (캐릭터마다 새 재질: `tint:"mask"` 셰이더 변형·외곽선·스킨·클립 목도리 …, 판 시작/캐릭터 첫 등장 때 한 번 멈춤 — 기존 `prewarm` 이 새 모델·스킨·mask 변형을 덮는지), ② **런타임에 .glb 읽기·텍스처 디코드** (판 시작/대기실에서 캐릭터 고르는 순간 동기 로드 3~4MB glb + 2048² 텍스처 → 수십~수백 ms, `ResourceLoader.load` 가 메인 스레드), ③ 스킨 메시 `Skeleton3D` 첫 사용·`MeshInstance3D` 생성·`External.attach` 가 한 프레임에 몰림, ④ 닌자 클립 층 (22트랙)·목도리 verlet·`Ext.sync` 65뼈 × 8몸을 한 프레임에 몰아서, ⑤ GC (매 프레임 Array/Dictionary 할당 — `Ext.sync` 의 `Basis`·`Transform` 임시 값은 괜찮지만 Dictionary 복제·`duplicate`·문자열 합치기), ⑥ 판 시작·KO·재시작에서 몸을 지웠다 다시 만들기 (`queue_free` + 재조립), ⑦ 래그돌 몸 조각 생성 (몸마다 11 + 10 관절).
C. 새 모델만의 문제가 아닐 수도 — 같은 조건에서 `--no-ext` 로 비교해 **차이를 새 모델 탓으로 좁혀라**.

## 할 일
1. **히치 로거 + 보고 도구 (PC 에서 재혁이 쓸 것)**: 기존 `core/perf.gd`·`--frame-log`·F3 패널 위에 **프레임 시간이 평균의 2배 (또는 25ms) 를 넘으면 히치로 기록** — 시각·프레임 ms·그 프레임에 **무슨 일이 있었나** 태그 (판 시작/카운트다운/KO/부활/필살기·스킬 발동/새 캐릭터 첫 등장/몸 만들기/셰이더 첫 사용/로드/방 입장, `prof` 구간 중 제일 긴 것) 를 `user://hitches.txt` + F3 패널 '히치 N회·최악 xxms·원인 상위' 한 줄 + '복사' 한 줄에 포함. 꺼져 있을 땐 비용 0. 재혁은 다음 판 뒤 이 한 줄만 붙여 주면 됨.
2. **헤드리스/소프트웨어 환경에서 가능한 측정** (GPU 시간은 못 잼, 나머지는 잼): 판 시작·캐릭터 선택 (모델 로드·인스턴스·attach·prewarm) **CPU ms 를 새 모델 4명 + 예전 몸으로 각각 재서 표로** (히치 후보 B①~⑦ 의 크기), 8명 판 프레임당 `bodies.update`·`Ext.sync`·클립·목도리·래그돌 구간과 **프레임당 할당·GC** (`Performance.get_monitor` 오브젝트 수·메모리 증가), 삼각형·그리기 수·영상 메모리 (판 중 8명 새 모델 vs 예전 몸).
3. **고치기 (측정이 가리키는 곳부터, 새 모델 모습·PC 동작은 그대로)**: 후보별 대응 예
   - 모델·텍스처를 **판 시작 전에 (대기실/로딩 중 백그라운드 `ResourceLoader.load_threaded_request`) 미리 로드**, 판 중 처음 나오는 캐릭터가 동기 로드를 안 하게; 로드한 `PackedScene`·텍스처 캐시 재사용 (몸을 지우고 다시 만들 때도).
   - 셰이더 prewarm 을 새 모델 재질 (mask tint·외곽선·스킨·1인칭 vm·목도리 클립 층) 까지 넓혀 첫 사용 컴파일 제거 (`tools/shader_check.gd` 로 목록 확인).
   - 판 LOD 한계 (~8.5k, UV 이음선): 외곽선 껍데기 메시를 판 LOD 에서 더 가볍게 (외곽선은 단순 메시로 — 같은 정점으로 법선 확장이라 삼각형은 같지만 먼 몸은 외곽선 끄기/`pose_lod.gd` 와 같은 거리 기준), 먼 몸 (카메라에서 멀거나 시야 밖) 은 클립 층·목도리·`Ext.sync` 갱신 간격 늘리기 (`world_config.gd POSE_LOD*`), 텍스처 밉맵·압축 (VRAM 압축 `.ctex` 가 이미 있는지, 2048² → 필요하면 1024² 로 판 LOD 전용 아틀라스).
   - 프레임당 할당 줄이기, 한 프레임에 몰리는 일 (몸 8개 `body.pose` 가 같은 프레임) 을 프레임에 걸쳐 분산.
   - 2880×1800 에서는 3D 렌더 해상도 배율 (`gfx_calc.gd` 고사양이면 높음 유지하되 8명 판 새 모델 켜면 자동 0.85~0.9 같은 보정은 측정이 요구할 때만).
4. 효과는 **전후 숫자 표**로 (같은 조건): 판 시작·캐릭터 선택 CPU ms, 프레임당 CPU ms 구간표, 그리기 수·삼각형·영상 메모리, 히치 후보별 크기. 소프트웨어 렌더라 GPU ms 는 못 잼 → 그 한계 명시, 대신 그리기·삼각형·메모리로 환산.
