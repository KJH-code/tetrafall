# W29 — 고도 웹판 성능 (친구가 브라우저로 들어가면 뜨지만 너무 느림·끊김)

재혁 결정 (2026-11-06): "고도 웹은 포기하지 않고 계속 시도". 증상: 웹 빌드는 **뜨지만 너무 느리고 끊김** (친구 PC·브라우저 미상 — 로컬 `--ext` 새 모델(탱크·닌자·사냥꾼·갈고리) 기본 켬이 되면서 무거워졌을 가능성 큼. v0.1.8 이후). 웹은 PC 주력의 '맛보기' (재혁 방침). 브랜치 `w/W29` (= 작업 브랜치 1a2103b).

## 배경
- 웹 = 고도 4.7.2 GL Compatibility (`project.godot` 에 `rendering_method.web` 고정), **싱글스레드 wasm** (`web_nothreads_release.zip` 배포 템플릿, `godot/client/export_presets.cfg`, 서버가 `/play/` 로 서빙, 파일마다 `.br`·`.gz` 미리 압축, `godot/server/tools/package.mjs`). 직접 빌드한 작은 웹 템플릿은 `w/W5` (미병합, `build-web-template.sh`·release.yml web-template job — 크기 줄이기용, 속도 아님).
- 웹의 병목 후보: ① **CPU** (GDScript 가 wasm 위에서 PC 보다 몇 배 느림 + 싱글스레드) — 8명 몸의 `body.pose`·`Ext.sync` (65뼈 × 8명)·클립 층 (닌자 22 트랙)·목도리 verlet·래그돌 (cannon 식 몸 조각)·Lod·`pose_lod.gd`, ② GPU/드로우콜 (스킨 메시 + 외곽선 next_pass, 새 모델 판 LOD 가 ~8.5k 삼각형으로 예전 몸 ~1.3k/명보다 훨씬 많음), ③ **로딩·메모리** (모델 glb 3~4MB × 4 + 텍스처 2048 × 4, pck 크기, 첫 셰이더 컴파일 멈춤), ④ 대기실 3D 무대·타이틀·메뉴 배경.

## 할 일
1. **측정 (추측으로 고치지 말 것)**: 웹 빌드를 만들어 (`godot --headless --export-release Web`, 웹 템플릿은 `~/.local/share/godot/export_templates/4.7.2.stable/web_nothreads_release.zip` — 없으면 받기) 로컬 서버(`godot/server`, JS 서버도 가능)로 띄우고 Playwright (헤드리스 크롬, 사전 설치됨 `require('playwright')`) 로 8명 판 (봇 7명, 서버 `--bots`/대기실 봇 추가) 을 몇십 초 돌리며 `prof` 구간 (`client/core/perf.gd`·F3, `--frame-log`·`--census`·`tools/` 참고) 으로 **프레임 ms 를 구간별로** (몸 포즈·래그돌·Ext.sync·클립·목도리·월드·렌더 명령) 찍고, `--no-ext` (예전 몸) 와 `--ext` (새 모델) 를 같은 조건에서 비교. 헤드리스 크롬은 소프트웨어 GL 이라 GPU 시간은 의미 없음 — **CPU 쪽 시간과 드로우콜·삼각형 수·메모리·로딩 시간·전송 크기**를 본다. (SwiftShader 가 너무 느리면 `--use-gl=angle --use-angle=swiftshader` 옵션 조정.)
2. **고치기 (측정이 가리키는 곳부터, 닌자·탱크·사냥꾼·갈고리·예전 몸 PC 동작은 그대로)**:
   - 웹에서만 켜는 가벼운 길: `OS.has_feature("web")` 이면 새 외부 모델 대신 예전 구운/코드 몸 (삼각형 ~10배 적음) 을 기본으로 (설정에 '웹 새 모델' 켜기·`?ext=1` 같은 스위치는 남겨 둠), 또는 웹용 더 가벼운 LOD (이음선 한계 ~8.5k 라 새 UV 필요 — 비용 크면 보고만).
   - 웹 화질 프리셋 강제/기본 (`world/gfx_calc.gd`: 외곽선 끔·그림자 끔·MSAA 끔·렌더 해상도 배율 0.75·먼 몸 포즈 간격↑·래그돌 가까운 몸만·목도리/클립 층 끔), 설정 창에서 올릴 수 있게.
   - 로딩: 모델·텍스처를 웹에선 필요한 캐릭터만 (대기실에서 고른 캐릭터 + 판에 나오는 캐릭터), 첫 셰이더 컴파일 멈춤 줄이기 (이미 있는 prewarm 점검), pck 크기 (`export_presets.cfg` 웹 제외 파일: tests·tools·`ext_hold`·안 쓰는 모델).
   - 프레임 시간이 PC 의 N 배인 구간은 웹 전용 느슨한 갱신 주기 (30Hz 서버 틱과 맞춰 몸 포즈를 2프레임에 1번 등) — 판정은 서버라 안전.
3. 목표: 8명 판 **봇 7명 + 나** 에서 웹 CPU 프레임 시간을 PC 대비 몇 배로 줄였는지 전후 숫자로 보고 (수치 목표: 한 프레임 CPU 16ms 이하를 노리되, 환경 한계로 못 맞추면 얼마까지 줄었는지 정직하게). 웹 기본이 예전 몸이 되더라도 괜찮음 — 재혁이 "PC 주력, 웹은 맛보기" 라고 했고, 새 모델은 PC 에서.
4. 검증: `tests/run_tests.gd` (227 기준, 웹 프리셋·웹 기본 몸 테스트 추가 — `OS.has_feature("web")` 는 테스트에서 강제 가능하게 함수로 감싸기), `tools/shader_check.gd` (xvfb gl_compatibility), `node --test godot/server/tools/package.test.mjs` (6, 웹 묶음 건드리면), 웹 빌드가 실제로 뜨는지 Playwright 로 대기실 진입까지. 측정표·캡처 경로 보고 (커밋 금지, 단 측정 스크립트는 `godot/client/tools/` 나 `tools/` 에 커밋).
