# W23 — 외부(Tripo) 몸: 래그돌·1인칭 팔·모션 다듬기 (닌자 기준)

재혁 피드백 (2026-11-05, v0.1.7 `--ext` 닌자를 직접 해 봄): "일단 별로인 게 ① 래그돌 ② 1인칭 팔 ③ 기존 모션을 여기에 넣는 것".
인터뷰 답: 래그돌 = **몸이 뻣뻣하고 안 쓰러짐 + 예전 몸과 움직임이 달라 어색** / 1인칭 팔 = **모양·크기 이상, 공격 모션 어색, 깨져 보임(가시·구멍·잘린 단면)** / 모션 = **새 모델에 맞는 새 애니메이션** (코드 자세를 뼈에 옮기는 걸로는 부족).
브랜치 `w/W23` (= 작업 브랜치 a838c39). 같은 시각 W22 가 탱크 쪽(w/W22)을 하고 있음 — **탱크 파일·`tank.*` 는 건드리지 말고 닌자로 만들되, 로더(`external.gd`)·viewmodel·ragdoll 같은 공용 코드는 모든 외부 몸(탱크 포함)에 통하게** 고칠 것. 합칠 때 충돌은 통합 쪽이 처리.

## 먼저 (원인부터)
스크린샷·캡처로 지금 상태를 재현하고 원인을 갈라라 — 추측으로 고치지 말 것:
1. **래그돌**: `--ext` 닌자가 맞음·낙사·압사·경직·KO 에서 어떻게 움직이나. 코드 몸은 `client/ragdoll.gd` 가 cannon-es 식 몸 조각 11·관절 10 을 굴리고 골반을 판정 위치에 끌어당기며 쓰러졌다 일어남 (RAGDOLL_SLUMP). 외부 몸은 우리 관절 노드를 따라 뼈가 `Ext.sync` 로 맞춰짐 — 래그돌 관절을 넣은 뒤 sync 가 도는지·뼈 방향 맞춤(A 회전)·골반 높이 비율·뼈 회전 제한 때문에 뻣뻣한지, 몸 비율(팔다리 길이)이 달라 래그돌 조각(캡슐)과 안 맞는지 측정. 코드 몸과 같은 입력(같은 KO)을 두 몸에 주고 프레임을 나란히 비교한 캡처를 만들어 보고.
2. **1인칭 팔**: 지금 방식(`vm_from` 팔꿈치 아래 삼각형 가르기 / `vm_node` 닫힌 팔) 의 어디가 깨지는지 (닌자 W21 보고는 "안 깨짐"이었지만 재혁은 가시·구멍·잘린 단면·크기·모션을 봄 — 화면 해상도·FOV·카메라 가까이에서 보임, 1인칭 콤보·스킬·표창 중 어느 프레임인지 찾기).
3. **모션**: 코드 자세(`figure_motion`·`moves`)를 뼈에 옮길 때 새 몸 비율 때문에 어색한 동작 목록 (걷기·달리기·점프·평타·스킬·필살기·맞음·쓰러짐).

## 해결 (재혁 선택: 새 모델에 맞는 새 애니메이션)
- **애니메이션 클립을 만들어 넣기**: 닌자 뼈대(Mixamo 이름)용 키프레임 클립을 Blender 파이썬(`tools/blender/tripo/`)으로 만들어 `ninja.glb` 에 넣기 (AnimationPlayer 클립: idle·walk·run·jump/fall·land·평타 1~4·스킬·필살기·맞음·KO 쓰러짐 …, `Ext.play_clip` 는 이미 있음 — 어디서 부를지 연결, 코드 구동 자세와 섞기(upper-body 마스크 등)는 최소로). 서버 판정·타이밍(`MOVES` 시간)에 맞게 클립 길이·타격 순간을 정렬. 손으로 만든 포즈 키프레임이라 품질 한계가 있으면 정직하게 보고 (Mixamo 라이브러리는 로그인이 필요해 자동화 불가 — 재혁이 다운받아 줄 수 있으니 필요하면 요청 목록을 정리해 보고).
- **래그돌**: 외부 몸에서 쓰러짐이 코드 몸처럼 힘 빠져 쓰러졌다 일어나게 (뼈 제한·sync 순서·골반 끌기 조정), 보이는 몸이 판정과 어긋나지 않게.
- **1인칭 팔**: 닫힌 1인칭 전용 팔 메시 (모델 소매·장갑 모양을 따르고, 크기·위치는 코드 몸 1인칭 팔과 같은 화면 자리, 외곽선 포함 가시·구멍 없음), 평타·표창·스킬 모션이 새 클립/코드 자세로 자연스럽게.
- 닌자 단검 attach 등 W21 결과 유지. 코드 몸/연습·튜토리얼/`--ext` 없는 기본 실행은 그대로.
