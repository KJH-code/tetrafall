# W8 고도 타이틀·메인 메뉴를 JS 판과 같은 '맛' 으로
## 배경
재혁이 같은 화면 두 장을 나란히 보여 줌 (scratchpad 의 user-js-menu.webp = JS, user-godot-menu.png = 고도 Release v0.1.0 의 메뉴). 재혁: '타이틀 화면·메인 메뉴가 맛이 없다, JS 와 다르다'. 보이는 차이 (스크린샷 직접 볼 것):
- 로고: JS 는 기울인(italic) 흰 글자 + 청록 네온 글로우 + 로고를 가로지르는 빛 줄기·렌즈 플레어. 고도 v0.1.0 은 기울임 없는 흰 글자 + 얇은 초록 외곽선, 글로우 없음. (W4 가 기울임·빛을 일부 고쳤지만 아직 릴리스에 없음 — 현재 브랜치 기준으로 다시 확인)
- 3D 배경: JS 는 이번 테마(버섯 숲) 의 발광 갓·빛 알갱이(motes)·거울 바닥 반사·블룸으로 화려함. 고도는 거의 검은 실루엣·평평함, 블룸·발광·반사·알갱이가 안 보임.
- 버튼: JS 는 반투명 유리 같은 어두운 청남색 + 얇은 청록 테두리 + 왼쪽 빛 띠 + 글자 자간 넓음. 고도는 불투명 보라 + 두꺼운 초록 빛 테두리.
- 부제: JS 는 가늘고 자간 넓음, 고도는 굵고 빽빽함. 이름 칸 모양·핑 칩(오른쪽 위 '핑 4ms') 도 대조.
- 타이틀 화면 자체 (블록이 떨어져 쌓여 로고가 되는 연출, 빛 터짐, 빠져나가기) 도 JS 와 같은지 확인.
## 재혁 PC 실측 사실 (추가)
- 화면: 2880×1800 (16:10), Windows 배율 200% (권장값). 즉 논리 해상도는 1440×900 이고 물리는 2880×1800 (약 5.2Mpx, 1280×720 의 5.6배). GPU: 노트북 Intel Core Ultra 7 (내장) + RTX 5070 (하이브리드). 전원은 꽂음. 고성능 GPU 지정을 해도 랙이 남았음 → 이 해상도에서 4× MSAA + 전체화면 후처리 + 외곽선 패스가 겹치는 채움률 비용이 유력.
- UI: 고도는 기준 해상도 대응이 없어 1280×720 설계가 2880×1800 에서 같은 픽셀 크기로 그려져 매우 작게 보임 (window/stretch 없음, DPI 인식 확인 필요).
## 목표
1. 현재 통합 브랜치 (W4 반영) 기준으로 JS 의 타이틀·메뉴 장면을 7개 테마 각각 (?title=<테마 id> 로 고정) 과 고도 같은 테마를 같은 창 크기로 찍어 나란히 (Playwright / xvfb --auto … --shot, autopilot.gd 머리 참고) 보고, 차이 표 (항목 · JS 위치 · 고도 위치 · 고침/그대로 · 이유) 를 만든다. 시간 맞춤: JS 는 느려서 같은 순간이 안 찍히니, 로고 완성 뒤 정지한 장면을 기준으로.
2. 차이를 고친다: 블룸·글로우 (고도 Compatibility 렌더러가 WorldEnvironment glow 를 지원하는지 먼저 확인 — 안 되면 JS 블룸 패스와 같은 효과를 가산 합성 셰이더·글로우 스프라이트로 내기, 비용은 W6 가 만든 F3 숫자·그리기 수로 재서 보고), 발광 소품·빛 알갱이·거울 바닥·렌즈 플레어·로고 빛 줄기, 메뉴 버튼 재질·자간·부제·이름 칸·핑 칩. '그래픽 낮춤'이면 JS 처럼 블룸·반사를 끔.
3. 성능: 이 장면은 재혁 PC 에서 타이틀부터 랙이 났다는 보고가 있음. 새로 넣는 효과마다 비용을 재고 (그리기 수·SubViewport·전체화면 패스), 내장 그래픽용 낮은 화질 경로를 같이 둔다 (W6 의 자동 화질 연결).
