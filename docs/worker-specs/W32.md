# W32 — 최적화 3차 (그림자·CPU 소소한 비용·렌더러 점검)

재혁 (2026-11-08): "다음 최적화". 브랜치 `w/W32` (= `w/W31` 59e6347, 곧 작업 브랜치에 합쳐 v0.1.12). W31 이 적응형 3D 해상도·판 LOD 5/4/3천·외곽선 거리 끄기를 넣음. 재혁 F3/히치 한 줄은 아직 없음 → 측정 가능한 것 (그리기 수·삼각형·영상 메모리·CPU ms) 위주 + 설정으로 켜고 끌 수 있게. 같은 시각 W33 이 `chars/external.gd`·`ext_clips.gd`·애니메이션·모델링을 만지는 중 — **겹치지 말고 world/·그림자·렌더 설정·월드 쪽만**.

## 할 일 (측정 → 효과 큰 것부터, 새 모델 모습·PC 동작은 그대로)
1. **그림자 비용** (W31 측정: 해 그림자 패스 = 3D 삼각형의 38%, 71.7k): 그림자 패스에서 몸을 **가장 낮은 LOD 로** 그리기 (그림자 전용 저폴리 — `GeometryInstance3D` 에 그림자 전용 메시 쓰기가 안 되면 `cast_shadow` 를 LOD 메시마다 따로 켜고 끄기: 화면용은 LOD n, 그림자 캐스터는 LOD 3 만 `SHADOWS_ONLY`), 먼 몸·시야 밖 몸 그림자 끄기 (거리는 `pose_lod.gd`·`outline_far.gd` 기준 맞춤), 그림자 거리·캐스케이드 (`world_config`) 를 판 크기·카메라 높이에 맞춰 조정, 블록·지형 그림자는 정적이면 갱신 줄이기. 효과는 삼각형 전후 (`--census`).
2. **CPU 쪽 소소한 비용**: 닌자 몸 그리기 14회 (단검 조각 ×6 + 몸) → 단검 조각을 하나의 메시/재질로 합쳐 8회 감소 (`ninja.glb` 소품, `rig_ninja.py` 의 `--dagger`), 먼 몸의 `Skeleton3D` 갱신 간격 늘리기 (`Ext.sync`·클립 층·목도리: pose_lod 먼 몸), 판 시작 8명 몸 만들기 한 프레임에 몰림 분산, 래그돌 몸 조각 먼 몸 끄기 확인.
3. **렌더러 점검**: GL Compatibility 외에 Mobile/Forward+ (`start-lan-mobile/forward.bat`) 로 켰을 때 8명 판에서 그리기 수·셰이더 컴파일 ms·삼각형이 어떻게 다른지 가능한 범위에서 (vulkan lavapipe 에서 shader_check 가 안 끝나는 알려진 문제 — 시간 제한으로 끊고 측정 가능한 것만) 보고. 결정 (기본 렌더러 바꿀지) 은 재혁 F3 한 줄이 필요하니 **바꾸지 말고** 비교표만.
4. **Windows 하이브리드 GPU**: 노트북 (Intel 내장 + RTX) 에서 게임이 내장으로 도는 문제 확인·대응 — `start-lan*.bat` 의 레지스트리 `UserGpuPreferences` (이미 있음) 가 실제 exe 이름·경로와 맞는지 `package.mjs` 로 확인, 시작 시 로그/F3 에 GPU 이름 + '내장 GPU 로 도는 것 같음 (설정 > 시스템 > 디스플레이 > 그래픽에서 고성능 지정)' 경고 줄 (GPU 이름에 Intel/UHD/Iris 가 있고 고성능 GPU 가 따로 있는지 `RenderingServer.get_video_adapter_name` 만으로 가능한 범위), 대기실 '설정' 도움말에 한 줄.
5. **검증**: `tests/run_tests.gd` (263 기준, 새 테스트: 그림자 캐스터 LOD, 먼 몸 그림자 꺼짐, 닌자 단검 합침 그리기 수, GPU 경고 판정 함수), `tools/shader_check.gd` (xvfb gl_compatibility, 0 에러), `node --test godot/server/tools/package.test.mjs` (6), 4명 캡처 전후 (그림자 모습이 크게 안 바뀌는지, 닌자 단검 위치). 전후 표 (삼각형·그리기 수·영상 메모리·그림자 패스 삼각형). 소프트웨어 렌더 한계 명시.
