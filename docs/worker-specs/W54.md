## 할 일 (이 순서, 앞 단계 결과를 `docs/w54/README.md` 에 먼저 쓰고 다음으로)
1. **측정·제안서 (코드 수정 전)**: 캐릭터별(닌자·탱크·사냥꾼·갈고리) 평타·스킬마다 ① 서버 판정 사거리·활성 구간·회복 구간 ② 보이는 무기 끝이 그 활성 구간에 실제로 닿는 거리·시각(클립 프레임)을 표로. 어긋남(거리·시간) 크기순 정렬.
2. **사거리 맞춤**: 보이는 쪽을 늘릴 수 있는 것(무기 모델·팔 IK 뻗기·한 걸음 앞딛기 보정)부터 시도하고, 서버 사거리를 줄여야 하는 것은 **줄이는 폭이 작은 것만** (재혁 승인 범위: 판정이 눈에 보이는 무기 끝에 가까워지게. 사거리를 늘리는 변경은 하지 말 것). 변경 목록과 이유를 표로.
3. **타이밍 맞춤**: 탱크 주먹·방패 올려치기·사냥꾼 베기의 `moves` 활성/회복 구간을 클립 타격 프레임에 맞추거나(서버 쪽), 클립을 서버에 맞추기(클라 쪽) 중 팝이 더 줄고 규칙 영향이 작은 쪽. 전후 팝 수 (W52 와 같은 연습 재연 4명 ×3회).
4. **밸런스 확인**: 규칙을 바꾼 캐릭터는 전후로 봇 판 시뮬레이션(C#/고도 쪽 도구가 있으면 그것, 없으면 JS `npm run sim` 은 JS 판용이라 참고만)·단위 테스트로 승률 기대값·평균 딜 변화를 비교해 큰 변화(±10% 이상)가 있으면 되돌리고 보고. 규칙 변경은 끌 수 있게 (`--old-moves` 또는 config 스위치) 해서 재혁이 PC 에서 비교 가능하게.
