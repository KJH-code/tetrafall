# W46 — 모션 개선 4차: QA 가 남긴 결함 (2026-11-13)

W44 모션 QA (`docs/w44`) 가 데이터로 남긴 결함 — 탱크 허리 삼각형 늘어남, 달리기 다리 팝, 발 미끄러짐 판정 불신, 슬러프 180° 팝, 천 끝 떨림 — 을 같은 방법 (눈 아닌 수치) 으로 다시 재현하고 고침.
모든 수치는 소프트웨어 렌더 (xvfb + llvmpipe) 에서 **렌더를 끈 채 뼈 포즈·메시만** 읽어 쟌 것 — 움직임의 맛·무게감·화면 속 부드러움은 수치로 못 잡으니 재혁 PC 확인이 필요 (맨 아래).
서버 판정·`moves` 시간·`figure_motion` 규칙은 안 건드림 (`node tools/game-hash.js` 기준선 `bf2e2951…4cc34` 그대로 확인).

## 3·4. 걸음: 박자 배율·보폭을 새 판정으로 다시 고름 + 옆걸음 골반 yaw

새 판정 (1절) 으로 W34 값 (`stride [k 1.4~1.45, c, 박자 ×1.6]`) 을 격자로 훑음 (`gait_qa --sweep`, 캐릭터 × 걷기·달리기 × 박자 0.35~1.6 × k 0.8~1.4):

- k > 1 (보폭 늘리는 2본 IK) 은 전 격자에서 **다리 팝과 미끄러짐 비 둘 다 나쁘게** 만듦, k ≤ 1 은 IK 를 안 거치고 (`external.gd` 가 `k > 1.0` 일 때만 IK) 팝 0. → **k = 1.0** (IK 끔).

## 5. 슬러프 180° 팝 (닌자 대시 팔 129°·래그돌 복귀) — 시도 후 되돌림 (보류)

재현·원인: 닌자 대시 시작 (표창 wind → 대시 strike) 의 오른팔이 **코드 자세 (fade_from) 와 대시 클립 자세가 거의 반대 (회전 차 ~170°)** 여서, 크로스페이드 `Quaternion.slerp` 의 '최단 경로' 가 클립이 조금만 움직여도 이쪽·저쪽으로 뒤집혀 한 표본에 129° 튐 (`--qa-bone-trace RightArm --qa-trace 1` 로 표본별 값 확인). Godot 의 `slerp` 는 이미 `dot < 0` 이면 부호를 뒤집으니 **'부호 반전' 을 더하는 건 소용없고 문제는 dot ≈ 0 근처**.
시도: 페이드를 시작할 때 한 번 dot 부호를 정해 끝까지 같은 쪽 호로 (`slerp_raw` 직접 구현) → 닌자 대시 129° → 74° (두 표본에 나눠짐) 로 줄었지만 **사냥꾼 몸 팝 94 → 122, 최악 각속도 110° → 157°** (긴 호로 돌게 된 표본) 로 다른 결함이 늘어 **되돌림**. 직전 결과에 가까운 호 고르기 (연속성) 도 시도했으나 닌자 166° 로 더 나빴음.
남은 해결 후보 (재혁 판단): 대시 시작 크로스페이드를 길게 (지금 공격 진입 0.10초 고정 — 타격 순간이 서버 판정과 같아야 해서 건드리지 않음), 또는 대시 클립 첫 자세를 코드 표창 wind 끝 자세와 가깝게 Blender 에서 다시 만들기. 래그돌 복귀 한 표본 팝은 8명 판 재연이 래그돌 물리 비결정 (W44 ±15) 이라 전후를 신뢰할 수 있게 못 잼.

## 2 (뒷부분). 탱크 허리 앞 천·어깨 장갑의 작은 2차 모션 — 보류
