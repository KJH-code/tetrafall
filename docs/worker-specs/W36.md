# W36 — 웹·배포 마무리 (작은 웹 템플릿, 첫 화면 시간, 배포 안정성, 렌더러 선택)

재혁 (2026-11-09): 지금은 애니메이션·모델을 못 받음 → "나머지부터". 이 워커는 **웹판·배포·렌더러** 쪽. 브랜치 `w/W36` (= 작업 브랜치 c893c8d, v0.1.13). 같은 시각 W34 가 `chars/`·몸 재질, W35 가 `ui/`·`fx/`·월드 버그를 함 — 겹치지 말고 `godot/server/tools/package.mjs`·`.github/workflows/release.yml`·`export_presets.cfg`·`core/opts.gd`·웹 관련 world 설정·`tools/web_*.cjs` 만.

## 배경
웹 = GL Compatibility 싱글스레드 wasm. W29 가 웹 기본 경량화 (예전 몸·화질 낮음·외곽선 끔·pck 10.5MB) 를 넣었으나 wasm 39.5MB 는 그대로, 첫 화면·첫 셰이더 컴파일 멈춤은 못 잼. v0.1.13 배포는 GitHub 일시 장애로 두 번 실패 (템플릿 tpz 잘림, cloudflared 504) 후 성공 — 재시도 보강은 템플릿만 했음.

## 할 일
1. **작은 웹 템플릿 (`w/W5` 병합 검토)**: 미병합 `w/W5` (`build-web-template.sh` = scons `threads=no optimize=size_extra lto=full build_profile` + 안 쓰는 모듈 끔, release.yml `web-template` job, 캐시 키 = 고도·emsdk 버전 + 스크립트 해시, `package.mjs --web-template`/`GODOT_WEB_TEMPLATE`) 를 현재 브랜치 위로 가져와 (cherry-pick/merge, 충돌 정리) **wasm 크기·로딩 시간이 실제로 줄어드는지** 측정 (`tools/web_first.cjs`, 전송 크기 br 기준 전후). 빌드가 40~60분 걸리니 이 환경에서 직접 빌드가 어려우면 (emsdk·scons 있으면 시도, 없으면 시간 한도 내에서) 병합만 하고 release.yml 의 job 이 정상 동작하는 문법·캐시 검증 (`yaml`·dry-run) 과 **켜기/끄기 스위치** (기본: 표준 템플릿 유지, 변수로 작은 템플릿) 까지 만들어 보고. 첫 릴리스에서 빌드가 150분 job 을 넣으면 릴리스가 너무 길어지니 기본은 끔이 안전.
2. **웹 첫 화면 시간·첫 셰이더 컴파일 멈춤 측정**: Playwright 로 웹 빌드를 열어 (1) 주소 입력 → 첫 그림 (타이틀) 까지 (wasm 내려받기·컴파일·`index.pck` 읽기, 네트워크 스로틀링 4G/Wi-Fi 흉내) (2) 첫 대기실 입장 때 CPU 멈춤 (소프트웨어 렌더라 셰이더 컴파일 시간은 대략) 을 표로. 큰 것을 줄임: pck 를 필요한 것만 먼저 (로딩 화면에서 진행률 표시 — 이미 있으면 정확도), 오디오 지연 로딩, 첫 화면이 길 때 안내 문구. 웹 `?quality=`·`?no-ext=` 등 `Opts` 인자 문서화 (`docs/godot-play.md` 웹 절).
3. **배포 안정성**: `package.mjs` 의 cloudflared 내려받기 (`download()` 4회 재시도, 각 2분 timeout 에 504 연속) 를 **캐시 + 실패해도 릴리스는 나가게**: (a) `actions/cache` 로 cloudflared 바이너리 (태그별) 보관, (b) 그래도 못 받으면 그 플랫폼 zip 은 cloudflared 없이 만들고 경고 + 릴리스 노트/`README.txt` 에 '터널은 직접 cloudflared 설치' 안내 (Windows 주력이라 Linux 만 해당할 수 있으니 플랫폼별 선택적), (c) 재시도 간격 줄여 전체 시간 상한 (15분) 안에. `release.yml`·`package.test.mjs` (7 → 새 테스트: 다운로드 실패 시 경고와 함께 계속, 캐시 있을 때 네트워크 안 씀) 업데이트. Actions 로그 읽는 법을 `docs/` 한 줄.
4. **렌더러 선택 (PC)**: 재혁 F3 데이터가 아직 없어 기본 렌더러는 **안 바꿈**. 대신 `start-lan-compat/forward/mobile.bat` 사용법을 `docs/godot-play.md` 에 한 절 (언제 어느 것, 확인할 F3 줄, 렌더러 비교표 `godot/README.md` 링크), 실행 중 설정 창에서 **현재 렌더러 이름** 표시 (F3 에 이미 있으면 확인), 재혁이 세 렌더러로 각각 한 판씩 하고 F3 한 줄씩 보내는 **측정 안내 문구** 를 대기실 도움말 또는 문서로.
5. **마무리 확인**: 릴리스 zip 에 `README.txt`/`docs` 의 최신 사용법 반영 (v0.1.13 기능 — 적응형 해상도·히치 로거·내장 GPU 경고), 웹 묶음 크기·파일 수 확인.
