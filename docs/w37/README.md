# W37 — PC 최적화 4차: 프레임 전체를 분류별로 재고 큰 것부터 (2026-11-09)

재혁 F3 숫자는 아직 없음 → 소프트웨어 렌더 (llvmpipe, GPU ms 못 잼) 에서 믿을 수 있는 것: **그리기 호출·삼각형 (화면 / 해 그림자 패스)·영상 메모리·CPU ms·객체 수 (누수)·로딩**. 모든 표는 같은 장면·같은 조건 (1280×720, 보통 지도 '반딧불 버섯 숲' 19×19, 8명, 높음 화질, `replay --budget`) 에서 전/후.

## 1. 도구

| 도구 | 하는 일 |
| --- | --- |
| `core/budget.gd` + `replay.gd --budget` | 보이는 3D 물체를 분류 (몸 외부/코드, 1인칭 팔, 지형, 쌓인 블록, 떨어지는 칸, 건축, 위험, 효과, 아이템, 이름표) 로 나누고 **분류마다 그 물체만 끄고 그려** 창·SubViewport 의 그리기·삼각형 (화면 + 그림자) 이 준 만큼 = 분류의 몫 (합이 전체와 맞음). 그림 메모리 (겹치면 처음 분류), CPU ms (`Prof` 구간 → 분류), SubViewport 목록 (크기·갱신·MSAA), 영상 메모리 |
| `tools/frame_budget.cjs` | 장면 (녹화) 여럿을 돌려 위 표를 한 번에 마크다운으로. `node godot/client/tools/frame_budget.cjs --godot <godot> --rec-dir <.rec 폴더> [--res 1280x720] [--only a,b] [--compare 지난.json] [--save 이번.json] [-- --set third=true]`. xvfb 없이 실제 GPU 면 `--no-xvfb`. GPU ms 는 이 표에 없음 (F3 패널·히치 로거) |
| `tools/rec_chars.mjs` | 녹화의 플레이어 캐릭터를 바꿔 새 녹화 (새 모델 4명 ×2 판·섞인 판·예전 몸 판을 서버 없이) |
| `tools/rec_loop.mjs` + `replay --mon-every <초>` | 녹화를 N번 이어 붙여 긴 판 (9바퀴 330초) 을 재연하며 물체·자원·노드·고아·정적 메모리를 일정 간격으로 찍음 (누수) |
| `tools/leak_probe.gd` | 캐릭터 몸을 만들고 지우기를 되풀이하며 객체·자원·노드·정적 메모리가 늘어나는지 |

녹화는 15MB 라 레포에 안 둠: `--rec` 로 자동 조종 판을 녹화하거나 `rec_chars.mjs game8.rec out.rec ninja,tank,hunter,hook,ninja,tank,hunter,hook`.

## 4. 재어 보고 안 한 것 (효과 없음·근거 부족)

- **칸 모양 거리 LOD** (먼 떨어지는 칸·쌓인 칸을 108삼각형 낮은 모양으로, 16m): 구현해 재 봤으나 8명 판 1인칭 −1.5k·3인칭 −1.0k 삼각형 (<1%) — 19×19 판의 칸이 거의 다 16m 안이라 → **되돌림** (코드 복잡도만 늘). 쌓인 칸이 150개+ 일 때 큰 이득이 날 수 있으나 이 재연에는 그 장면이 없음 (녹화 보충 필요).
- **이펙트 동시 다수** (`--fx-probe all`: 풀 상한 꽉 채움): 그리기 157 → 197 (+40, 대부분 몸 효과 노드 + 풀 5), 물체 +70 — 풀이 MultiMesh 상한 (파편 160·고리 12·빛 160·연기 64·돌 64) 에서 멈춰 더 안 늚. 손댈 것 없음.
- **대기실 전용 리소스 해제**: 판 중 숨은 SubViewport 합 2.7MB (대기실 큰 캐릭터 543×582 1.2MB·초상 등) — 이득 없음.
- **HUD/2D**: 상태 스냅샷마다 갱신 (`_on_state`), 프레임마다 도는 건 0.3ms 안팎. 2D 그리기 79~91 · 삼각형 1.3~1.7k, 소프트웨어에서도 CPU 1.2~1.5ms (용암 판에서 3.0 — 위험 경고 화면 요소, 따로 안 봄).
- **통신·GC**: 고도는 참조 세기라 GC 멈춤 없음. 스냅샷 한 번 JSON ≈ 0.35ms (13KB) · 프레임당 할당 +0.4KB (330초 재연 정적 메모리 +5.9MB 가 거의 시작 직후 캐시). 로그 출력은 프레임마다 없음.
- **텍스처 메모리**: 새 모델 한 명당 영상 메모리 +6~12MB (탱크 12.1·닌자 10.3·사냥꾼 6.4·갈고리 10.1) — glb 하나에 판 LOD 3장 + stage 2048² 가 같이 올라가 안 쓰는 LOD 아틀라스가 상주. 줄이려면 glb 를 LOD 별로 쪼개야 해서 (Blender 파이프라인·W38 클립 작업과 겹침) **보류**.
- **새 모델 몸 외부 메시 삼각형 (몸 하나 5000 × 외곽선 2)**: 3인칭 몸 80k 가 가장 큰 덩이지만 LOD·외곽선 굵기는 W31 이 이미 거리로 줄임 — 더 줄이면 모습이 바뀜 (가까운 몸의 외곽선·LOD 단계). 재혁 F3 (GPU ms) 를 본 뒤에.
- **하늘 블록 (반투명 0.88) 낮은 모양**: 떨어지는 칸 30.6k 의 대부분이 하늘 계단 블록이라 효과가 크지만 모습이 바뀜 → 보류.

## 5. 소프트웨어 렌더의 한계

GPU ms·VSync·드라이버 파이프라인 캐시·내장/외장 차이는 못 잼 (llvmpipe CPU 래스터). 래스터가 스크립트와 같은 코어를 써서 렌더 켠 스크립트 ms 는 렌더 끈 값보다 1.5~2배 — 순수 스크립트 비용은 렌더를 끈 재연 (`--replay` 에서 `--replay-render` 뺌) 으로. 삼각형·그리기·메모리·객체 수·로딩은 PC GPU 와 같은 코드가 내는 같은 숫자라 믿을 수 있음. 영상 메모리는 Mesa 가 보고하는 값 (MSAA 렌더 대상 포함, Vulkan 은 1.7~2배 — README 렌더러 비교표). 재혁 PC 의 F3 복사 줄 (GPU ms·1% low·히치) 이 이 표의 다음 근거.
