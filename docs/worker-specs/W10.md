- 이번 세션에서 이미 한 번 고쳤다고 봤던 감사 항목 C1 ('방 나가도 대기실 HUD 가 메뉴 뒤에 남음', `client/main.js leftRoom`·`hideRoomHud`·`hideRoomPanels`) 의 재발. 재혁 PC (실제 크롬, 빠른 프레임) 에서는 여전히 남음. 스크린샷 `/tmp/claude-0/-home-user/8deab670-0f99-5600-9c8d-a97e79b14e53/scratchpad/user-js-results-overlap.webp` 는 다른 그림일 수 있으니 (저장이 어긋났을 수 있음) 아래 설명도 같이: 메인 메뉴 (로고·'방 만들기' 펼침) 위에 오른쪽에 '라운드 1 결과' 판 (STEVE 승리, 이름·캐릭터·승·피해·결과 표) 과 맨 위 점수 띠 'P1 0 : 1 STEVE' 가 그대로 떠 있음. 판이 끝난 뒤 결과를 본 상태에서 방을 나갔을 때로 보임.
- 메인(오케스트레이터)이 본 단서: `client/main.js` 의 `updateHud()` (≈1996행) 는 `uiHold() && wipeHoldState` 이면 `state = wipeHoldState` 로 바꿔 `drawHud()` 를 돌림 (전환 띠가 덮기 전엔 지난 스냅샷으로 그림). 그런데 `leftRoom()` 은 `playWipe(wipeKind(screenNow,'menu'))` 를 직접 부르면서 `wipeHoldState` 를 건드리지 않음 → 지난 전환 때 저장된 오래된 스냅샷 (결과 화면의 state) 이 남아 있으면, 메뉴로 가는 띠가 도는 동안 `updateHud` 가 그걸로 결과 판·위 점수 띠를 다시 그리고, 띠가 끝난 뒤 `state === null` 이라 `drawHud` 가 바로 return 해서 아무도 다시 숨기지 않음. 가설이니 확인할 것. 메인이 해 본 것: `leftRoom()` 에 `wipeHoldState = null;` 한 줄을 넣어 봤으나 느린 헤드리스 (swiftshader) 에서는 고치기 전에도 재현이 안 돼서 효과를 확인하지 못해 되돌림 (아직 적용 안 됨).
- 재현 요령: 빠른 프레임이 필요하면 `--use-gl=swiftshader` 대신 `--use-angle=swiftshader` 등을 시험하거나 해상도를 작게 (400×300) 해서 프레임을 올리고, 방을 나간 직후 100ms 간격으로 `#results`·`#score`·`#center`·`#players` 의 hidden 클래스를 읽어 (나가기 전환 띠 `plan.ms` 이후에도) 보임 여부를 기록. 결과 판이 뜬 직후(`resultsHero` 중) 나가기·결과가 대기실 판으로 바뀐 뒤 나가기 · 연습/튜토리얼 방 나가기 · 설정 창 '방 나가기' 등 경로 모두. 재현 안 되면 `wipeHoldState`·`screenNow`·`uiHold()` 를 계측해 로그로 가설을 검증하고, 확신 없으면 방어적으로 `updateHud` 가 `state === null` 일 때 항상 방 HUD·패널을 숨기게도.
- 고침 뒤: `npm test` 통과, 방을 나가는 여러 경로 후 `#results`·`#score`·`#center`·`#players`·`#spec`·`#bottom` 이 전부 hidden 인지 Playwright 로 (띠가 끝난 뒤 1.5초) 확인.
