## 할 일
1. **합친 뒤 영상 메모리 +21MB 의 정체 확인 (회귀인지)**: v0.1.15 통합 보고에서 같은 종류 장면 (8명, 새 모델) 의 영상 메모리가 W37 보고 155.2MB 보다 176.2MB 로 높았음 (녹화 조건이 달라 비교 불가). **같은 녹화·같은 인자**로 `w/W37`(e85da35) 단독, `w/W38`(f6bdcb3) 단독, 합친 상태 (694d84a) 를 `--replay <녹화> --budget` 으로 재서 어디서 늘었는지 (W38 클립 에셋 `*_anim.glb`? 새 텍스처? 1인칭 보정?) 가르고, 회귀면 고침, 아니면 '조건 차이' 로 결론.
2. **새 모델 LOD 텍스처 상주 줄이기** (W37 보류 항목: 몸 한 명당 영상 메모리 +6~12MB, 안 쓰는 LOD 텍스처가 같이 올라옴): 새 모델마다 stage 알베도 2048² (대기실·초상·1인칭용) + 판 LOD 알베도 1024² ×3 (+ 마스크 텍스처 1024² ×3) 가 한꺼번에 올라가 있음. **판 중에는 stage 알베도가 필요 없는 몸 (남의 몸)** 이면 LOD 텍스처만, **대기실·초상·1인칭**에서만 stage 를 쓰도록 텍스처를 **필요할 때만 올리고 안 쓰면 해제/미로드** (`external.gd` 의 `_surfaces`·`toon_for` 텍스처 연결, `ResourceLoader` 캐시, `ext_lods` 선택). 같은 캐릭터가 여럿이면 텍스처 공유 유지. 판 중 LOD 가 높음/보통/낮음 중 하나만 쓰이면 나머지 두 LOD 텍스처는 안 올림. 영상 메모리 전후 표 (대기실·판 새 모델 8명·4명), 첫 그리기 멈춤이 안 늘게 (W30 미리 읽기·미리 그리기와 호환), 모습 회귀 캡처.
3. **떨어지는 칸 삼각형 (W37 표: 새 모델 8명 3인칭 삼각형의 24% = 30.6k, 칸 84개 → 칸당 ~365)**: 테마별 칸 모양 (`world/cells.gd`·`pieces_view.gd`·`piece_shapes`: 나무 상자+잎·사암 벽돌·보석·흑요석·대리석·버섯·돌 벽돌) 이 화면에서 작을 때도 같은 삼각형. 카메라 거리·화면 크기 기준 **칸 LOD** (먼/작은 칸은 단순 상자 또는 절반 삼각형), 같은 재질 칸은 InstancedMesh 유지, 하늘 블록 (하늘 시점) 낮은 모양, 화질 낮음은 이미 둥근 상자. 모습 차이가 허용 범위인지 캡처로 (끄는 인자 `--no-cell-lod`). 판 후반 (쌓인 칸 150개 이상) 장면 녹화를 새로 만들어 (rec_loop·rec_chars 도구) 쌓인 칸 쪽 삼각형도 측정.
4. **지형·먼 배경 (12% = 15.9k)**: 맵 테마 장식 (`blocks.gd` BlockDecor·먼 섬·산·하늘 구) 의 거리 LOD·화면 밖 컬링 (`VisibilityRange`), 그림자에서 장식 제외 여부. 모습 변화 있으면 전후 캡처, 끄는 인자.
5. **CPU 몸 자세 (렌더 끈 재연에서 몸 2.2ms/프레임)**: `bodies.update`→`body.pose`→`Ext.sync` 에서 프레임당 큰 구간 (`budget.gd` 몸 sync 구간 나눔 활용) 을 찾아 줄이기 (캐시된 Basis, 뼈 인덱스 사전 계산, 변하지 않은 관절 건너뛰기, 먼 몸 갱신 간격). 판정·모습 불변, 전후 ms (렌더 끈 값).
6. **측정 정리**: `frame_budget.cjs` 로 위 전후를 한 표에 모아 `docs/w39/README.md` 에 (장면: 새 모델 8명 3인칭·1인칭·전체 보기·예전 몸 8명·섞인 판·용암 판·판 후반). 소프트웨어 렌더 한계 명시.
