## 3. 공격·회복 구간 다리 팝

위 표의 다리 팝 28 → 4 는 대부분 2번 (복귀) 에서 사라짐 — 공격 `rec` 구간 다리 팝은 사실 공격 중 낙하 뒤 래그돌이 복귀하며 코드 자세 → 클립 자세로 넘어가던 것이었음. 남은 팝은 모두 **`moves` 설계값** (strike 가 0.08초에 클립 0.1초 분량을 지나감: 탱크 주먹 39×74°·방패 올려치기 34×48°·내려치기 14×50°, 사냥꾼 베기 29~25×59°·46°, 닌자 표창 wind 24×53°) → 클라이언트에서 줄이면 타격 순간이 판정과 어긋나므로 **서버 설계 변경 필요** (strike 길이를 늘리거나 클립 눈금 `marks` 를 캐릭터·동작별로). 코드↔클립 섞기 (cw) 속도를 자세 차이에 맞춰 늦추는 시도 (속도 비례·호 이어 고르기 2종) 는 4명 합 팝 수를 줄이지 못하고 일부 상태에서 긴 호가 새 팝을 만들어 폐기 (A/B 3회: 189 vs 195, 노이즈 범위).

## 4. 탱크 허리 앞 천·어깨 장갑 2차 모션 — 타당성

**이번엔 구현 안 함 (확신 못 함).** 판 LOD (high 5000·medium 4000·low 3000 삼각형, `relod`) 에 허리 앞 천·어깨 장갑이 별도 지오메트리로 없고 알베도 텍스처의 그림. 하려면 Blender 로 천 조각 (약 200~400 삼각형) 과 장갑 조각을 새로 모델링 → 뼈 (cloth_bones.mjs 식 사슬) 가중치 → stage 와 3개 LOD 모두 + 알베도 UV·텍스처 겹치지 않게 굽기 → 마스크 (붉은 목도리 칸) 와 `relod_merge` 재실행, 삼각형 예산 (8명 판 80k 높음 기준 한 몸 +300 × 8 = +2.4k, 크지 않음) 자체는 문제 없으나, 가장 큰 위험은 원본 텍스처의 그려진 천과 새 천이 겹쳐 보이는 것과 1인칭 팔 가르기·방패 클립과의 충돌이라 재혁 눈 확인 없이는 품질 보장 불가. 시도한다면 별도 워커로 천 한 장 (허리 앞) 만 먼저.
