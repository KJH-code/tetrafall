# W53 — 최적화 6차 (웹 시작 시간·입장 첫 프레임 남은 맵·객체 늘어남)

기준 = `6ba2e4d` (v0.1.21). 이 컨테이너 (코어 4, 다른 작업과 CPU 를 나눔, 소프트웨어 렌더 xvfb + llvmpipe) 값이라 ms 는 ±20% 흔들림. GPU 시간은 못 잼.
서버 규칙·`moves`·figure_motion 은 안 건드림 (`node tools/game-hash.js` = `bf2e2951…4cc34` 같음). 설정 창 모션 플래그·F6·pop_fix·`chars/` 는 안 건드림.

## 1. 웹 시작 시간

방법: 웹 내보내기 (`--export-release Web`, 공식 템플릿, 웹 기본 = 옛 몸 + 낮은 화질) 를 `web_start.cjs` 로 열어 첫 화면 (고도 로딩 막이 사라진 때) 까지 · 10Mbps·40ms 흉내와 네트워크 없음 (CPU 몫) 둘 다. brotli 11 로 미리 압축.

### 시간표 (전 = 6ba2e4d, 네트워크 없음, 소프트웨어 렌더)

| 단계 | 시각 (페이지 열고부터) | 비고 |
| --- | --: | --- |
| wasm·pck 다 받음 | 0.3~0.5초 | 로컬 서버라 받기는 거의 0 |
| `main _ready` 시작 | 0.9초 | 엔진 켜기 (wasm 컴파일·pck 읽기·자동 불러오기 4개) |
| `world 불러옴` / `추가` | 1.3~1.4 / 1.6~1.7 | 스크립트 파싱: 몸·외부 몸·g3 가 450~650ms (데스크톱 같음) |
| `title 추가` / `ui 추가` | 1.7~1.8 / 2.1~2.3 | 메뉴 판 110ms + 나머지 판 (대기실·HUD·결과·설정) 약 290ms |
| 프레임 0 → 프레임 1 | 2.4 → 3.7~4.0 | **첫 그리기 1.1~1.5초** (스크립트 아님 — 셰이더 컴파일) |
| 첫 화면 | **4.5~5.4초** | 로딩 막이 걷힘 |

첫 그리기 1.3초의 몫 (`?skip=` 과 타이틀 무대 조각을 빼며 가름, 같은 빌드, 1.3초에서 뺀 값): 타이틀 소품 (테마 따라) 약 0.7 · 로고 블록 0.45 · 빛 번쩍·불티 0.23 · 나머지 (월드 + 판) 0.24. 데스크톱은 같은 장면 첫 프레임이 0.4~0.5초 (웹 = WebGL → ANGLE 변환이 더해져 3배) — **재혁 PC 의 `hitches.txt` 로 다시 봐야** 실제 몫을 앎 (이 환경은 소프트웨어 GL).

### 고친 것: 효과음 wav 를 첫 pck 에서 빼 첫 화면 뒤에 받음

받는 양이 큰 조각: 첫 pck (br 7.68MB) 의 반 이상이 소리 — 효과음 wav 녹음본 (QOA, 325개) 이 약 4.2MB, 그 중 타이틀·앰비언트 핑 2.0MB 는 **7개 테마 몫인데 한 번 켜면 한 테마만 씀**. 웹 첫 화면에는 이 소리가 필요 없음 (첫 화면 뒤 메뉴·타이틀 소리부터).

- 내보내기 플러그인 (`addons/web_music/export.gd`): 웹일 때 `audio/baked/*.wav` 를 pck 에서 빼고 `PCKPacker` 로 **묶음 파일**: 공통 `sfx.pck` (2.9MB) + 테마마다 `sfx_t_<테마>.pck` (0.4~0.55MB, 타이틀 착지·빛 터짐·빠져나가기 + 앰비언트 핑). 곡 ogg 는 예전대로 `music/`.
- 런타임 (`audio/sfx_pack.gd`, `audio.gd` 가 붙임): 쪼갠 빌드 (웹 + 첫 pck 에 `swing.none.0.wav` 없음) 일 때만 켜져 첫 화면 뒤 30프레임에 받기 시작 → `user://` 에 저장 → `ProjectSettings.load_resource_pack`. 순서: **이번 메뉴 테마 → 공통 → 나머지 테마** (`music.gd` 가 앰비언트 테마가 바뀔 때 그 테마를 앞으로). 받는 동안 그 소리는 조용히 넘어감 (`sfx.stream` 이 null, 캐시 안 함 — 묶음이 붙은 뒤 다음 소리부터 열림). PC·옛 웹 빌드는 첫 pck 안에 그대로라 아무 일 없음.
- 웹 `HTTPRequest.download_file` 은 파일이 안 생겨서 (확인) 본문을 받아 직접 저장.

| | 전 | 후 |
| --- | --: | --: |
| 첫 pck br | 7.68MB | **3.83MB** |
| 첫 화면까지 받는 양 (wasm 6.90 + pck + 작은 파일) | 14.6MB | **10.7MB** |
| 뒤에 받는 양 (묶음 8개 br) | 0 | 4.28MB (공통 2.27 + 테마 7개 합 2.01) |
| 전체 | 14.77MB | 15.2MB (묶음을 따로 압축해 +0.4MB) |
| **10Mbps·40ms 첫 화면** | 16.5 · 17.0 · 17.3 · 17.9 (평균 **17.2초**) | 13.8 · 14.0 (**13.9초**, −19%) |
| 네트워크 없음 첫 화면 | 5.3 · 5.4 · 5.4초 | 4.7 · 4.8 · 5.3초 (pck 가 작아 올리는 일이 줄어듦) |

- 중간 단계 (공통 묶음만 빼고 테마 소리는 첫 pck) 는 10Mbps 16.0 · 16.1초 — 테마 쪽 2MB 까지 빼면 더 빨라짐.
- 후 10Mbps 값은 이제 wasm (br 6.90MB) 받기가 좌우. 직접 빌드한 웹 템플릿 (W5, 이 레포 `build-web-template.sh`, wasm br 5.39MB) 을 쓰면 −1.5MB (약 −1.2초) 가 더 있음 — 릴리스 워크플로 기본은 꺼짐이라 이번엔 안 건드림.
- 소리 확인: 웹 `?auto=host&bots=3` 판 35초 — 묶음 8개 9.2초에 다 붙고 (이 환경은 네트워크 없음이라도 프레임이 느려 받기가 몇 초), 효과음 177~205번 (묶음 없는 옛 빌드 152번과 같은 규모). 오류 0. 소리가 늦게 오는 구간: 메뉴 테마 묶음 → 공통 순서로 10Mbps 약 1~3초 (첫 화면 뒤).
- 사용자 PC 캐시: 묶음은 방문마다 다시 받음 (브라우저 HTTP 캐시가 있으면 서버가 정함). `user://` 저장본을 다음 방문에 쓰는 것은 안 함.

### 해 보고 안 한 것: 타이틀 소품을 첫 그리기 뒤 조각으로
`title_world.setup(defer)` + `setup_step` (대기실 W42·W51 이 쓰는 것) 로 타이틀 소품을 첫 프레임 뒤로 미뤄 봄 — 테마 7개 고정 (`?menu-theme`) 으로 전·후 비교: 첫 그리기 1.27 → 1.15초 (평균), 테마마다 −0.2~+0.1 로 잡음 안 (소품 셰이더가 다음 프레임에서 똑같이 컴파일됨 — 합이 같음). 이득이 근거 안 서서 되돌림 (코드 안 남김).
- 안 한 것 (비용 대비): 월드·판 패널 (대기실·HUD·결과·설정 ~290ms) 을 타이틀 뒤로 미루기 — `Gfx` 가 월드 안에서 `lowGfx` 를 정해 타이틀이 읽음, 순서 의존이 얽힘. 외부 몸 스크립트 (`external.gd` 등 ~250ms) 를 웹에서 안 불러오기 — 여러 파일 preload 를 풀어야 하고 웹 기본에서만 이득 (약 5%).

## 2. 입장 첫 바퀴 최악 프레임

방법: W51 과 같은 시나리오 (`--auto host --bots 7 --wait-players 8 --menu-wait 12 --start-delay 6 --hitch --lag-log --sched-log`, 480x270), 맵 테마 7개 `--menu-theme`, 입장 태그 프레임부터 `입장 첫 바퀴 끝` 뒤 2행까지, **멈춤 프레임 (벽시계 1초 넘음) 과 그 다음 프레임은 뺌** (W51 과 같음).

원인: W51 §1 의 '남은 큰 덩어리' — 대기실 판 첫 갱신 (`ui (HUD)` 12~13ms = 점수 띠 + 대기실 판 5~7 + 방장 판 + 얼굴 데우기 + HUD 카드) 이 월드 조각 (소품·몸 만들기 8~12ms) 과 **한 프레임에 겹침** — 큰 일 문 (`Gate`) 밖이었음.

고친 것 (`ui/ui.gd` `_refresh_panels`): 대기실 판 갱신을 **A (점수 띠 + 대기실 판)** 와 **B (얼굴 데우기 + HUD 카드 + 방장 판)** 둘로 나눠 입장 첫 바퀴 (`Gate.entered` 거짓) 동안 `Gate` 를 거침 (`ui.panel.a`·`ui.panel.b`, 예상 6ms). 못 돈 조각은 다음 프레임에 (`_panel_late`, 이미 한 조각은 다시 안 함). 첫 바퀴가 끝나면 문 없이 평소대로 (100ms 갱신).

## 3. 객체·메모리 완만한 증가

방법: `soak.mjs enter --n 100` (방 만들기 ↔ 나가기, 봇 3, 한 프로세스) 의 표본마다 `--soak-obj` 객체 census + 정적 목록 크기. `OBJECT_COUNT` 는 클래스로 못 나누지만 트리·속성을 걸어 셀 수 있고 **센 것과 총수의 차 = 트리 밖** (객체 8000~11000 중 4300~5100 이 트리 밖).

범인: 총수 증가 (입장당 약 +17) 는 **`ui_style._reg`** (화면 빛 등록부 — 판·버튼·글자 빛을 새 테마 색으로 다시 칠하려 `[WeakRef, 종류, 인자]` 를 기억) 에 쌓인 **사라진 컨트롤의 WeakRef** (`WeakRef` 도 객체 하나). 살아 있는 것은 입장마다 714개 그대로, 사라진 것이 입장마다 +17 씩 쌓여 **4000 (정리 한계) 까지 약 190번 입장** 동안 늘어남 → 포화는 하지만 소모만 됨 (rss 에는 거의 영향 없음 — 객체당 100바이트대). 나머지 늘어남은 정리 한계 있는 캐시 (`G3._mats` 입장당 +4 → 512 에서 정리, `_outlined` 오르내림, 자원 캐시 `res` 1034 → 1134 포화) 와 지도·캐릭터 첫 만남 때 계단.

고침: 정리 한계를 살아 있는 수 기준 `max(1024, 살아 있는 수 × 2)` 로 (`G3._prune` 와 같은 방식). 옛 동작은 `--no-reg-prune`. 테스트 `test_style_reg_prunes_dead_refs` (살아 있는 300개 유지·죽은 것은 한계에서 정리·끄면 옛 4000).

25ms 넘은 프레임 0 / 210 (전·후 모두). 무거운 곳은 몸 자세 4~7 + 칸 깔기 3~7 (mushroom 후 24.2 = 칸 깔기 6.9 + 몸 자세 6.9 가 같은 프레임) — 카운트다운 시작은 `W41` 이후 24ms 이내.

## 입장 4번째 프레임의 긴 멈춤 (이 환경 1.5~9초) — 찾아본 것
입장 태그 + 4번째 프레임에 생기고 (`entry split deferred frame 4`, 그 전·뒤 프레임은 정상) `rcpu_ms` (렌더 명령 CPU) 는 그 프레임 36ms 뿐 → 스크립트도 렌더 제출도 아니라 **GL 드라이버 (llvmpipe) 가 처음 보는 장면의 셰이더를 만드는 시간**. 그 프레임 = 월드 (대기실 8명·지형·칸) 를 처음 그릴 때 (타이틀 장면이 꺼지고 `world.visible`). 셰이더 이름은 이 환경에서 못 알아냄 (고도에 컴파일 목록을 찍는 길이 없음). 재혁 PC 에서는 `hitches.txt` 의 `첫 그리기 지연 의심` 으로 확인.
같은 방식 (웹 `?skip=`) 으로 웹 첫 그리기도 갈랐음 (§1) — 타이틀 소품 셰이더가 첫 그리기의 절반.

## 못 한 것·미확인

- 웹 첫 그리기 1.1~1.5초 (타이틀 소품·로고 셰이더 컴파일) 는 줄이지 못함 — 소품을 뒤로 미뤄도 합이 같았음. 실제 GPU 에서의 몫은 재혁 PC 의 `hitches.txt` 로.
- 직접 빌드한 웹 템플릿 (wasm br −1.5MB) 은 릴리스 워크플로 기본 꺼짐이라 건드리지 않음 — 켜면 10Mbps 첫 화면 약 −1.2초 더.
- 효과음 묶음: 받는 동안 (10Mbps 약 1~3초) 메뉴·타이틀 소리 일부가 비어 있음. 묶음을 `user://` 에 두고 다음 방문에 재사용하는 것과 묶음 버전 표시는 안 함. 묶음 받기 실패 (4번 시도) 면 그 판은 효과음 없이 — 로그 `[효과음 묶음]`.
- 입장 4번째 프레임 긴 멈춤의 셰이더 이름 (위) 은 미확인. 객체 증가의 나머지 (약 +11/입장) 는 포화하는 캐시로 결론, 200회 이상으로 포화를 직접 보지는 않음.
- 모든 ms·초는 이 컨테이너 ±20% (다른 작업과 CPU 를 나눔).
